§01

市场与时机

Market & Why Now

我们不在卖一本书，而在给一场正在发生的范式转移供给「语料级的知识基础设施」。Agent 生态越繁荣，对「可信、结构化、可商用」人文知识库的稀缺性就越强——现在是供给它的最佳窗口。

WHY-01

Agent 大爆发，但「可用的知识」是短板

2024–2026 年 Agent / RAG 应用指数增长，而通用语料（网页抓取、维基 dump）噪声大、无策展、许可模糊。高质量、结构明确、许可清晰的人文知识语料是公认的稀缺品。

WHY-02

Skill / MCP 把「知识」变成「可调用能力」

Claude Skills、MCP 等协议让知识库从「被检索的文本」升级为「被执行的框架」。本库 137 个 Skill 天然契合这一标准——这是纯文档库没有的时间窗口。

WHY-03

中文人文深度内容的「鸡汤化」真空

知识付费以简化换流量，严肃内容又锁在付费墙与学术黑话里。「拒绝简化、免费开放、对 Agent 友好」三个条件同时满足的库，在中文世界几乎空缺。

§02

目标用户与细分

Segments & ICP

四类人群，一个共同点：他们要的不是「更快的答案」，而是「更可信的思想结构」。优先级 P0 = Agent 构建者与深度学人——他们是启动口碑的两端。

ICP-A · P0

Agent 构建者

AI-native Developers
PAIN 痛点
给 Agent 喂维基语料太浅、喂爬取语料太脏；想要开箱即用的领域 Skill 与可追溯引用，且许可必须可商用。
GAIN 我们给的
137 个标准化 Skill（统一 frontmatter）、index.json 机器索引、10 类显式关联构成可推理图谱、CC BY-SA 全量开放。
首战切入：把「佛教认知 15 Skill + CSE 16 Skill」打包成两套示范 Skill 包，进 Agent 注册表分发。
ICP-B · P0

研究者与深度学人

Researchers & Scholars
PAIN 痛点
原典难读、学派互不通话；跨学科检索靠运气，没有一个「先建立整体感」的入口。
GAIN 我们给的
每条目 ~100 行建立思想家整体感，原典 / 研究 / 入门三层阅读阶梯，跨学科关联显式标注类型，可直接进文献综述。
首战切入：知乎 / 豆瓣连载「条目精读」，每篇以一个概念为透镜，文末链回全库。
ICP-C · P1

深度学习者与创作者

Lifelong Learners & Makers
PAIN 痛点
被鸡汤式内容喂养到反胃，想要不简化的第二遍学习；写作者需要跨人物的思想素材。
GAIN 我们给的
诊断式阅读：迷茫 → 马斯洛诊断，认知卡点 → 八识诊断，叙事困住 → 三性诊断；另有 99 张跨人物素材清单。
首战切入：少数派 / 即刻发布「用 Skill 给自己做一次认知诊断」互动文章。
ICP-D · P2

教育与文化机构

Institutions & Educators
PAIN 痛点
课程缺乏体系化、许可清晰的开放教材；佛学院 / 人文通识课缺一套可引用的现代知识底座。
GAIN 我们给的
佛学院五大支柱专题（戒律 / 三论 / 俱舍 / 唯识 / 五明）、CSE 学派体系——课程级模块 + 明确署名许可。
首战切入：向 3–5 所佛学院与 CSE 课程捐赠定制专题索引，换取教学场景背书。
§03

定位与信息

Positioning & Messaging

对于需要可信人文知识的开发者与深度学人，Open Cognition 是首个以「人类与 Agent 共用」为第一原则构建的跨学科认知数据库——它不是又一个百科，而是人可深读、机可调用的知识基础设施：拒绝鸡汤式简化，每一条都可追溯、可链接、可执行。

— POSITIONING STATEMENT · v1.0
i.

拒绝知识快餐

Depth over Digest

每条目附「原典 / 研究 / 入门」三层进阶阅读，保留学派争论与常见误读。我们卖的是「第二遍学习」，永远不与爽文比快。

ii.

人机同源

One Corpus, Two Readers

人类读条目建立整体感，Agent 调用 Skill 执行框架——同一份数据、同一套结构、同一份许可。这是本库与一切传统知识库的分界线。

iii.

关联即结构

Typed Links as Graph

同源 / 互补 / 对立 / 批判 / 继承……10 类显式关联让知识成为可追问「为什么相关」的图谱，而非孤立的词条堆。

受众一句话信息（对谁说什么）证据锚点主战场
Agent 构建者「别再喂维基 dump 了——这里有 137 个可直接挂载的人文 Skill，许可干净。」SKILL frontmatter 规范 · AGENT.md · index.jsonGitHub · Agent 注册表 · HN

深度学习者「迷茫的时候，让一千个头脑给你做一次诊断。」诊断式阅读 Skills · 素材清单少数派 · 即刻 · 小红书

真正的对手不是某个具体产品，而是「继续用维基 dump 喂模型」的默认选项。下表回答：用户为什么要把默认选项换成本库。

机器可调用 纯文本 dump 不可商用抓取 封闭 API 137 Skills + index.json，Agent 直接挂载

MOAT-01

结构复利

2400+ 条目间的显式关联一旦建成，每新增一条都在增强整张图谱——后来者可抄词条，抄不走关系网络。

MOAT-02

双读者的标准卡位

「人类条目 + Agent Skill」的统一 frontmatter 正在成为事实格式。谁先在 Agent 注册表里铺开人文 Skill，谁就定义类别。

MOAT-03

策展信任

质量准则 + 统一模板 + 拒绝简化的编辑立场，长期沉淀为「这里说的可以信」的品牌资产——信任是知识库最贵的护城河。

§05

渠道与分发

Channels & Distribution

开源知识库的渠道哲学：去知识已经在场的地方，而不是把人拉到新地方。P0 渠道是发布周的火力点，P1 是复利引擎，P2 是规模期权。

优先级渠道动作衡量
P0GitHub 有机 + SEOREADME 双语改写为「30 秒看懂」；permalinks 条目被搜索引擎收录；仓库 Topics 全配。外链点击 · 搜索收录条数
P0Agent 生态注册表把示范 Skill 包提交到 Claude Skills / MCP 目录与主流 agent runtime 示例；提供一行接入命令。Skill 安装量 · 被 fork 的接入示例
P0开发者社区发布v1.0 发布周：Product Hunt + Hacker News（英文帖）+ V2EX / 少数派（中文帖），统一叙事「给 Agent 的人文知识库」。发布周 stars · 讨论质量
P1人文学术社区知乎专栏 / 豆瓣连载「条目精读」；与哲学、佛学、CSE 读书会共创专题索引。连载关注数 · 条目深读率
P1通识学习者社区即刻 / 小红书「认知诊断」互动内容；每张素材清单切一条短视频脚本。互动率 · 新访客占比
P1Newsletter 双周报「本周一个概念 + 一个 Skill」固定栏目，沉淀私域复读者。订阅数 · 打开率 ≥ 40%
P2学术 / 国际渠道英文版上线后进 Reddit（r/philosophy、r/Buddhism、r/LocalLLaMA）与学术会议 poster。国际 stars · 引用次数
P2机构合作佛学院 / 高校课程捐赠定制索引，换教学场景背书与联合署名。课程采用数

※ 每条渠道只保留一个负责人、一个衡量指标；连续两周期无产出即降级或砍掉。

增长飞轮 · Growth Flywheel

  1. 条目被检索 / 被调用——搜索引擎与 Agent 注册表带来第一波精准访客。
  2. 访客变读者——三层阅读阶梯把一次点击变成一次深度会话。
  3. 读者变贡献者——模板与质量准则让贡献门槛低而质量稳。
  4. 贡献扩大图谱——新条目增强整网结构，搜索引擎与 Agent 更愿意引用。

§06

发布节奏

Launch Plan

以 v1.0 为点火点的四个阶段。每阶段有明确退出条件（Exit Criteria）——达标才进入下一阶段，不达标就留在原地打磨。节奏比速度重要。

Ph.0

地基

现在 → v1.0 前进行中

不发声，先把「可被引用的地基」打牢：发布动作一旦开始，每一次曝光都必须落在一个经得起打开的库上。

  • index.json 结构冻结并写版本承诺；AGENT.md 成为 Agent 接入唯一入口
  • 两套旗舰示范 Skill 包（佛教认知 / CSE）打包、可一行安装
  • 英文 Hero 页与「30 秒看懂」README 就位
EXIT：接入文档 10 分钟内可跑通一个最小 Agent 调用示例。
Ph.1

点火

v1.0 发布周

集中弹药打一次「品类宣告」：不是又一个百科，而是人机共用的认知基础设施。所有渠道同一周、同一叙事。

  • Product Hunt + Hacker News + V2EX / 少数派四线同发
  • 发布周每日一条「条目精读」内容弹药（预热 3 天 + 发布 + 续燃 3 天）
  • 收集 issue 与首批贡献者，48 小时内响应每一条反馈
EXIT：GitHub ≥ 1k stars，或任一 Skill 包 ≥ 100 次安装，且出现 5 位非核心贡献者。
Ph.2

生态

v0.10 → v1.x

从「被看见」转向「被依赖」：让 Agent 生态把本库当作默认的人文知识层。

  • MCP Server + Agent SDK 集成示例，接入从「复制文件」降为「一行配置」
  • 可视化关联图谱上线，跨域浏览成为传播素材本身
  • 英文版覆盖佛教认知与 CSE 两大旗舰专题优先
EXIT：月度知识调用（北极星）连续 3 个月环比增长 ≥ 20%。
Ph.3

规模

v1.x 之后

建立可持续性结构，让开放承诺与长期维护可以同时成立。

  • 赞助 / 基金会化运作（OpenCollective、NLnet 等开源资助）
  • 机构合作与课程采用进入制度化（模板化共创流程）
  • 托管增值服务（可选）反哺核心库维护
EXIT：维护成本被多元资金覆盖，核心贡献者 ≥ 15 人且领域分权。
§07

商业模式与可持续性

Business Model

本库的价值随引用与调用增长，而非随稀缺增长——所以正确姿势是永远开放核心，靠生态位变现。

Non-negotiable 不可谈判项

核心永远是 CC BY-SA 4.0，永远免费、永远可被 Agent 调用。

开放不是营销话术，而是分发策略本身：每一次合规商用、每一个 Agent 挂载、每一篇学术引用，都是本库的免费分销网络。任何收缩许可的行为都会摧毁整个 GTM 的前提。商业化只发生在生态位，不发生在核心上。

收入流 STREAMS

a.
赞助与资助

OpenCollective / 爱发电 + 开源基金（NLnet、OSF 类）——为「公共知识品」付费的正当通道。

PHASE 3 起重点
b.
托管增值服务

托管 MCP 端点 / 检索 API：免运维的即插即用版本，企业为便利付费，数据永远可自行拉取。

PHASE 3 期权
c.
教育与出版授权

课程共创、定制专题索引、纸质精选集——机构为「策展人力」付费，而非为内容付费。

PHASE 2 试点
d.
共创与咨询

为 Agent 团队提供「人文知识层接入」咨询，反哺核心库的接入体验。

按需 · 不主动扩张

§09

风险与对策

Risks & Mitigation

RISK-01 · HIGH扩张导致质量稀释

快速加条目复利最快，但一旦「鸡汤化」就摧毁唯一护城河。对策：质量准则（quality-criteria）为合并硬门槛；任何新领域先立模板与样例再放量；宁缺毋滥写进贡献指南。

RISK-02 · MEDAgent 生态格式漂移

Skills / MCP 标准仍在演化，押错格式会让 137 个 Skill 失去入口。对策：核心资产保持纯 Markdown + 最小 frontmatter，格式层做成薄转换器；跟随两大生态主流，不自造协议。

RISK-03 · HIGH维护者倦怠与单点依赖

2400+ 条目的维护强度对核心作者不可持续，倦怠是最现实的死亡方式。对策：领域分权 ownership；Issue 模板化降低协作成本；Phase 3 的资金结构以「让维护者可持续」为第一目标。

RISK-04 · MED版权与引用争议

综述类内容难免被质疑「搬运」；CC BY-SA 的署名要求在下游被忽略。对策：只存原创综述 + 完整出处层（sources）；提供标准引用格式；建立 takedown 快速响应流程。

RISK-05 · LOW大厂推出同类知识层

模型厂商自建人文语料的可能性存在。对策：中立、开放、可审计正是相对厂商自有语料的差异化；积极寻求被集成而非对抗——成为它们的供给方。
