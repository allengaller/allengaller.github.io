二

第一张工作单：架构设计

五步 · 五工具 · 五件套交付

岗位全景里第一张闭环交付的工作单。它把一次架构设计固定为五个可校验的步骤，每一步由一个结构化工具承担，产出落盘的工件，而不是留在聊天记录里。新手从这张单入门，老 SA 用它校准自己的流程。

01
需求澄清把对话提炼成结构化需求卡：业务场景、规模/并发、可用性目标、预算区间、合规约束。必填项缺失时主动追问。
structure_requirementsOA-T01 · 需求卡 schema
需求卡 JSON缺失必填项列表
02
方案生成Agent 按需读取 arch-design 技能：场景模式识别 → 参考架构选型 → 组件选型，产出方案文档。
skill: arch-designOA-SK-01 · 原生 Skill 接入
方案文档选型依据可追溯
03
架构图输出生成 Mermaid 架构图，语法校验失败自动修正重试（上限 2 次），并导出可编辑的 draw.io 文件。
validate_diagram · export_drawioOA-T02 / OA-T03 · 纯逻辑工具
Mermaid + .drawio校验通过才交付
04
WAF 评审按 aliyun-waf 五支柱清单逐项评估，校验覆盖完整性，计算评分表与高风险项清单。
review_with_wafOA-T04 · 机读清单
五支柱评分表 + 风险清单覆盖完整性校验
05
交付物打包把需求卡、方案、架构图、评审结果组装为一份 Markdown 交付文档，写入 ./deliverables/。
export_deliverableOA-T05 · 落盘交付
Markdown 交付文档五件套归档

技能资产

Markdown · 可审计 · 可替换

工作显性化的载体就是技能包：方法论文档是产品本体，Agent 是执行器。每个技能包是一个目录：SKILL.md + 知识正文 + 交付模板，经 AgentScope Toolkit 原生接入，Agent 按需读取。

arch-designskills/arch-design
需求分析框架、常见场景模式（Web 应用 / 数据平台 / AI 推理服务等）、选型决策树。
自研方法论 + 公开最佳实践
OA-SK-02
aliyun-wafskills/aliyun-waf
Well-Architected 五支柱检查清单与问卷条目，结构化供 review_with_waf 机读。

OA-SK-03
sa-playbooksskills/sa-playbooks
上云评估、迁移、成本优化等交付 SOP 与模板。
通用 SA 交付实践

边界与证据

路线图不冒充现状

这是开源项目，能力边界写在明面上：哪些工作单已经闭环，哪些还在路上。给评估者、未来的自己，和每一位考虑投入时间的 SA 一张诚实的表。

现在就能用MVP · 已实现

  • OA-C01第一张工作单：架构设计需求澄清到交付打包五步闭环，工具自动修正重试
  • OA-C02AgentScope 2.0 运行时ReActAgent + Toolkit + launch_console
  • OA-C03三个技能包Markdown 承载，框架原生接入，可改写可扩充
  • OA-C04模型可换DashScope 默认，任意 OpenAI 兼容端点
  • OA-C05Docker 交互式运行docker compose run openarch

在路线图上NOT YET · 别当现状

  • OA-R01售前其余工作环节客户洞察 / PoC 验证 / 投标支持 / 交付复盘
  • OA-R02学习路径与技能树新手成长地图，按阶段定位能力缺口
  • OA-R03产品级浏览器 Web UI基于 Agent Service + 官方 Web UI 扩展
  • OA-R04客户管理与交付沉淀客户档案、交付记录、复盘积累
  • OA-R05Runtime 服务化与多云知识包容器化多用户部署，AWS / Azure 选型知识
TESTING单元测试 CI 必跑Mermaid 校验器、drawio 转换、需求卡 schema、WAF 评分逻辑、技能包 lint，无需 API Key。
E2E端到端冒烟真实 Key 跑通五件套断言：需求卡 → 方案 → Mermaid → WAF 评分 → 交付文档。
SPEC设计规格先行MVP 设计文档与需求方逐节确认后实施，仓库内可查。
